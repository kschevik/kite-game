# Knut's Kite Game v1 — SUPER-LIGHT static browser game
Build in /workspace/kite-game/: index.html, style.css, game.js (plain JS, no build step, no dependencies, no network calls). Single <canvas> 2D, flat minimal graphics (solid colours, simple shapes). Colour-blind safe: NO red/green; use navy, cyan, yellow, orange, white, magenta. Mobile-first (iPhone Safari / Android Chrome), also desktop. Portrait layout friendly; canvas scales to window with devicePixelRatio. No console errors. touch-action:none, prevent scroll/zoom.

## Physics (port of physics_v4.md, simplified)
- True wind W (base 8 m/s; displayed in kn = m/s*1.944). Line length 22 m. Kite position on the wind window: angle theta (0 = edge/zenith side, up to window centre = power zone). Kite flies on a sphere quarter-window; draw as 2D: kite position (x,y) on screen within a window arc above the rider, power zone = a highlighted band to the side/lower part of the arc (draw it as a faint arc zone).
- Player steers the kite target position by touch drag (kite follows the finger with limited turn rate) or mouse drag / arrow keys / A,D / W,S. Kite velocity vk measured from its motion on the window (scaled to m/s: window radius 22 m). Apparent wind Va = |W_vec - v_kite| ; additionally board speed adds. Kite crosswind speed capped by L/D (4.5): Va <= W*sqrt(1+4.5^2) ~ 4.6W. Power-zone factor cos-like: zone weight zw = clamp(cos(theta_from_centre)) (edge/zenith ~0 extra, centre ~1).
- Pull R = (Va/W)^2 (1x parked ... 'normal riding' 2-4x, dive ~6x, hard loop up to ~10x, theoretical ~21x). Show a PULL meter (x1..x21) with zones: 1x edge, 2-4x normal, 4-6x dive, 6-10x loop, and a danger band >12x ('overpowered').
- Board speed grows with pull (smoothed, drag), shown in km/h or kn. Sinusoidal/figure-8 passes through power zone is the way to build speed; flying parked at edge/zenith slows you down and kite stalls (if kite speed < threshold at low position for >2.5 s: STALL -> lose points and speed, kite flutters, "STALL" message). If pull > ~14x for >0.7 s: OVERPOWERED -> crash (yank, lose points, short respawn/recovery, lose speed).
- Random magic gusts: every 6-12 s a visible gust (sparkly/white streaks sweeping in from the left, a 'GUST!' label) briefly boosts W x1.6 for ~2.5 s, with a shimmer. Gust boost is shown on the HUD wind.
## Waves & jumps
- Ocean in side view: rider on a board on water at the bottom, scrolling waves (simple sine ramps, flat colours) come from the right, speed of scroll tied to board speed. A wave ramp approaches; a visible timing marker/"POP" button (and Space / tap button big at bottom-right, also double-tap not needed). Pressing POP while on the wave face near the lip = perfect (bonus, higher jump); early/late = small jump or none. Show "PERFECT / GOOD / EARLY / LATE" feedback. Jump launch velocity = f(board speed, pull, timing quality). Airtime and height computed from simple ballistic + kite lift (extra lift while kite is in power zone/flying). Height in metres, shown big during jump, max height recorded.
- Tricks in the air: (1) KITELOOP / HELILOOP: while airborne, doing a loop with the kite (circular drag gesture or button 'LOOP' / key L) adds lift (extra upward acceleration for ~1 s, +height) and big points; mistimed loops cost a stall. (2) 'GRAB' button/key G (hold during air for points per sec, small). (3) 'SPIN' button/key S or swipe-left/right on the rider... keep simple: buttons: LOOP, SPIN, GRAB. Tricks give trick points; landing with a spin/loop must complete (rotation fully done) else 'sketchy landing' penalty. Landing must be at/after reaching water; bad landing (overrotated) costs points. Score = round(max_height_m*100 + trick points + perfect pop bonus) minus penalties (stall, crash).
## Run structure
- A run lasts 60 seconds (timer), then 'RUN OVER'. Each run has several waves (a wave every ~6-8 s). Score is accumulated across jumps in the run; run height = best jump height in the run. Start screen: title "Knut's Kite Game", short how-to (3 lines), Start button; shows local best (localStorage 'kkg_best') and, if URL has ?h=12.4&s=3400 (challenge), the target: "Beat Knut's 12.4 m jump (3400 pts)" banner shown on start screen and in HUD, and at end "You beat it!" or "X m short".

# v2 additions
Same constraints as v1 (plain JS, no deps/network, one 2D canvas, palette navy/cyan/yellow/orange/white/magenta + tints, NO red/green), but index.html+style.css+game.js < 110 KB. All v1 features and hooks stay.
## A) Graphics (lightweight, ~60 fps on phones)
- Parallax sky: clouds (individual rates 0.03–0.14×) and two mountain ridges (0.012× and 0.035×) offset by board distance × px/m, plus a horizon haze band.
- Particles (screen space, cap 140): spray from the board tail while riding above 7 m/s (≈9·(v−7) per s); a burst of 12–40 on every landing (size grows with impact speed and jump height).
- Canopy: leading-edge tube and 3 struts in yellow; trailing edge pulled deeper with pull and fluttering more when depowered (stall/crash = pull 0); magenta gradient that darkens with pull; size scales with √(kite/9).
- Rider poses: grab (hand to rail), spin (tucked, rotating), kiteloop (body stretched, bar up toward the kite), board-off (legs dangling, board drawn apart, drifting and rotating, then snapping back over 0.18 s), handle pass (bar behind the back while rotating). The kite line attaches to each pose's bar position.
## B) New tricks (airborne only, need an active jump)
- BOARD-OFF (button "BOARD OFF", key B, hook `boardOff()`): once per jump. Second press (or auto at 0.8 s) catches it: +400 + 400·min(t, 0.8)/0.8. Landing while off = bad landing (−300, speed ×0.4, no board-off points). Caught < 0.2 s before touchdown = sketchy landing (−150).
- HANDLE PASS (button "PASS", key H, hook `handlePass()`): needs ballistic time-to-water ≥ 0.45 s, otherwise "TOO LOW" and nothing happens. Rotates 360° over 0.7 s; when done, +600. The open rotation at landing is added to any unfinished spin rotation and judged like v1 spins (> 0.35 rad sketchy, > π/2 bad).
- `state()` adds `boardOff, passing, spinning, looping, grab, lastLanding ('clean'|'sketchy'|'bad'|null; crash in the air = 'bad'), tricks (names landed this run: KITELOOP, HELILOOP, SPIN, GRAB, BOARD-OFF, HANDLE PASS), trickCounts, setup {kite, line, wind}, particles`.
- Buttons: two rows (LOOP SPIN GRAB / BOARD OFF PASS) left of the round POP; fits 390 px (smaller below 350 px).
## C) Setup screen
- START (#startBtn) opens the setup overlay (phase 'setup'); GO! (#goBtn) starts the run. PLAY AGAIN reuses the setup; CHANGE SETUP reopens it. `__kite.startRun()` starts immediately with the current setup; `__kite.setSetup(o)` sanitises, applies and saves.
- Kite 7/9/12 m: pull scale k_kite 0.75/1/1.35, turn scale 1.25/1/0.75. Line 15/22/27 m: window radius (kite m/s = normalised motion × L), turn × 22/L, kite speed ceiling × (L/22)^0.3, drawn window radius ∝ (L/27)^0.6. Wind slider 10–30 kn (step 0.1, default 15.6): W = kn/1.944.
- Pull R = k_kite·(Va/8)² (identical to v1 for 9 m / 15.6 kn), so big kite + strong wind hits the overpowered band (R > 14) much sooner. The setup screen warns when k_kite·(kn/15.6)² > 1.8.
- Sanitising: kite snaps to the nearest of {7, 9, 12}, line to the nearest of {15, 22, 27}, wind is clamped to 10–30 (1 decimal); non-numbers fall back. Stored in localStorage 'kkg_setup'.
- Challenge link adds `k, l, w` (e.g. `?h=12.4&s=3400&n=Knut&k=9&l=22&w=16`), parsed with the same numbers-only regex as h/s. If present they preselect the setup (over the saved one), and the banner says "… on 9m · 22m · 16kn".
- The setup is shown in the HUD (`9m · 22m · 16kn`), on the results screen and on the share card ("9 m kite · 22 m lines · 16 kn").
